Build a Complete Multiplayer Web Game: PENALTY GRID

You are an elite game designer, senior full-stack engineer, multiplayer systems architect, UI/UX designer, motion designer, and football-game designer.

Your task is to BUILD the game described below as a genuinely playable, polished web application.

Do not create a mockup, prototype, static demo, landing page, or fake multiplayer simulation.

Build the actual game.

The game should feel like a polished modern party game that people could realistically play with friends for hours.

⸻

1. GAME CONCEPT

The game is called PENALTY GRID.

It combines:

* Football penalty shootouts
* Football player knowledge/trivia
* A 3×3 grid
* Prediction
* Bluffing
* Risk/reward
* Fast decision-making
* Multiplayer competition

The fundamental question of every penalty is:

Can you name a footballer who satisfies BOTH criteria of the square you selected?

The shooter chooses where to shoot.

The goalkeeper chooses where to dive.

Both decisions are hidden until the reveal.

⸻

2. THE 3×3 GRID

Every penalty displays a football goal divided into a 3×3 grid.

There are:

3 horizontal criteria

and

3 vertical criteria.

Every square is therefore the intersection of exactly two criteria.

Example:

	Premier League	La Liga	Serie A
Argentina	Argentina + Premier League	Argentina + La Liga	Argentina + Serie A
World Cup Winner	World Cup Winner + Premier League	World Cup Winner + La Liga	World Cup Winner + Serie A
Played for Liverpool	Liverpool + Premier League	Liverpool + La Liga	Liverpool + Serie A

The player selects one square.

The game then presents the two criteria associated with that square.

The player has a limited amount of time to name a valid footballer satisfying BOTH criteria.

⸻

3. SHOOTING

When it is the player’s turn to shoot:

1. Display the 3×3 goal.
2. Player chooses one square.
3. Their selected square becomes locked.
4. Start a countdown.
5. Player must provide a footballer’s name.
6. Validate the answer against the football database.

If the answer is invalid:

MISS

The ball should visibly miss the goal.

If the answer is valid:

The shot is ON TARGET.

The goalkeeper now has a chance to save it.

⸻

4. GOALKEEPER MECHANIC

Before the shooter reveals their answer, the goalkeeper secretly chooses one of the nine squares.

The goalkeeper is predicting where the shooter will shoot.

The goalkeeper’s choice must remain hidden.

After the shooter answers:

CASE A: Goalkeeper chose the WRONG square

The shot automatically becomes a:

GOAL ⚽

Animate the ball entering the goal.

CASE B: Goalkeeper chose the SAME square

The goalkeeper correctly predicted the shot.

However, the goalkeeper is NOT automatically given the save.

The goalkeeper must now name a DIFFERENT footballer who satisfies the SAME TWO criteria.

Example:

Criteria:

Argentina + Serie A

Shooter:

Paulo Dybala

Keeper cannot answer:

Paulo Dybala

They must provide another valid player, for example:

Lautaro Martínez

If the goalkeeper’s answer is valid:

SAVED 🧤

If the goalkeeper’s answer is invalid:

GOAL ⚽

This creates a second layer of football knowledge.

⸻

5. IMPORTANT ANSWER RULES

The shooter and goalkeeper must never be able to use the same footballer for the same penalty.

Answers must be validated against actual football data.

Do NOT rely purely on an AI model to determine whether an answer is valid.

Create a structured football-player database or data layer.

The system should support:

* Player name
* Alternate/common names
* Nationality
* Clubs
* Club history
* Competitions
* International appearances
* International team
* Major trophies
* Relevant attributes needed by the criteria system

The answer validator should handle reasonable variations in player names.

For example:

“CR7” should resolve to Cristiano Ronaldo if appropriate.

But completely ambiguous or incorrect answers must be rejected.
